**Status:** done
**Written by:** Claude · **Date:** 2026-11-17 · **Plan:** `docs/plans/TRD.md` § T10

## Goal
`#/sectors` has 1 day (`d1`) and 1 week (`w1`) only (`RotationPeriod` in `src/utils/sectorRotation.ts`).
Add 1 month (`m1`) from real daily closes. The IDX trace step (`idxTraceStep`, server.ts ~4436) already
reads each stock's close every trading day; keep a compact rolling table of the last 30 closes.

## Allowed files
- New `src/utils/idxCloses.ts` + new `src/utils/idxCloses.test.ts` (pure: append a day, compute 1M)
- `server.ts`: **only** (a) inside `idxTraceStep`, after a stock's close is known, add it to the rolling
  table (load once per step, save once at the end with `setPacked('idx:closes', …)`), and (b) in
  `buildSectorRotation` pass each stock's 1M change to the pure module. New store key `idx:closes` allowed.
- `src/utils/sectorRotation.ts` + its existing test (add period `m1`)
- `src/components/SectorRotationView.tsx` (third period button "1 month")
- `src/i18n/en.ts`, `src/i18n/id.ts` (new keys only)

## Logic
- `idxCloses.ts`: `{ dates: string[] (≤30, ascending), closes: Record<symbol, Array<number|null>> }`.
  `appendDay(table, date, symbol, close)` keeps arrays aligned with `dates`, drops the oldest beyond 30.
  `change1m(table, symbol)` = latest close vs the close 21 trading days earlier, `null` if either missing.
- `sectorRotation.ts`: `RotationPeriod = 'd1' | 'w1' | 'm1'`; add thresholds for `m1` (FLAT 0.5,
  DRIVER_MIN 2) and use the 1M value in `chgOf`. Quadrant logic stays 1W vs 1D (do not change).
  For `m1` drivers: only monthly drivers (Pink Sheet) and BI-Rate apply; live drivers → none.
- UI: before 22 dates exist, the 1 month button shows the sectors with "Not enough history yet"
  instead of numbers. Never fill with estimates.

## Tests

sector 1M cap-weighted from fixture rows.
